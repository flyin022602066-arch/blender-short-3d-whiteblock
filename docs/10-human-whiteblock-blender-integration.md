# 仿真人白模与 Blender CLI / MCP 接入方案

状态：2026-10-08 已实施人体模板、三维关键点驱动、官方 CLI 与内置 MCP。下文保留设计依据；更高质量的视频人体模型求解器、真实相机求解、服装/道具与完整场景重建仍属后续能力。

## 人物性别模板边界

系统区分的是 Blender 渲染用的**男型 / 女型 / 中性人体模板**，不是从画面推断人物的性别身份。每个镜头的人物轨迹独立编号；没有用户资料时使用中性并标为“待确认”。在桌面端“人物与模板”页选择模板并保存后，才会写入 `template_confirmed=true`、`template_source=user`，并要求当前镜头重新渲染。模板变化不会覆盖旧视频，仓库会提示“模板已修改，视频仍为旧模板”。

后续 Agent 请求包会把已确认的 `actor_templates` 和角色名附在原有提示词中；未确认角色标记 `needs_confirmation`，模板已变但尚未渲染标记 `pending_render`，不会把旧人体视频当成可直接使用。Blender 场景摘要和修订 JSON 保留相同元数据，供再次渲染和外部流程读取。选择“中性”也必须由用户明确保存；新检测轨迹的默认中性仍是待确认。

## 群演可见性与漏检修复

群演处理使用 `output/models/yunet/face_detection_yunet_2023mar.onnx` 做头部锚点，按相邻帧位置和头部尺度进行全局匹配，再把锚点交给 MediaPipe。这样身体姿态短暂漏检时仍保留该人物的完整人体；补出的姿态写入 `pose_source=anatomical_prior` 和 `prior_pose_samples`，用户可在质量报告中区分实测姿态与先验补全。`bake_human` 同时给人体和骨架插入 `hide_viewport` / `hide_render`，人物不在轨迹时二者一起退出。

这套机制修复了原片 `shot_003` 的群演问题：原工程存在 6 条断续轨迹，修订后稳定为 5 条轨迹，73 帧均可渲染；所有抽查帧人体与骨架可见性一致。修订输出另存，旧 `.blend` 和 MP4 保留。头部定位能改善漏检，不能恢复被完全遮挡人物的真实动作、身份或三维深度。

## 当前使用

“连接与设置”的白模质量默认选择 `human_v3` 和 `eevee`。回到概览选择原片，一键转换会创建连续人体、164 根命名骨架、蒙皮和细分表面，使用世界/画面关键点逐帧驱动，再检查人体之间及前臂/躯干的变形网格相交并尝试修正，最后输出工程、视频和每镜头质量 JSON。无法确认的下肢保留正常骨架姿态，不按画外的错误关键点抬入近景。

仓库选中预览后点击“连接 Blender / Agent 修正”，软件打开独立 Blender 编辑会话并连接 MCP。当前是项目自己的 MCP stdio 服务与本地认证桥接，未安装第三方通用自由编码插件。可在 Agent 中说“查看场景”“检查穿模”“把 Actor_01 的左手放到胸前”“重渲染”。在线 Agent 使用既有 Eggfans 通道，接收参数 schema 与当前场景信息；多个人物且没有明确编号时，手部预设会要求指定目标。

可用 MCP 工具：场景查询、跳帧、当前帧预览、变形网格检查、手脚 IK 目标、手部预设、镜头构图、男/女/中性同拓扑轮廓切换、另存工程。重渲染会先保存修订，再用 CLI 输出新的单镜头项目与 MP4 并入库；不会把一个修改的镜头冒充整段新视频。原完整视频和旧工程保留。

模板使用 MakeHuman 核心 CC0 网格、骨架、权重与 MPFB 核心体型目标，未安装整个 MPFB 插件。文件在 `output/models/makehuman_cc0`，来源提交、Git blob 与 SHA-256 在 `asset-manifest.json`；CLI 创建人物前核对资产哈希。成品 `.blend` 内保存网格、权重、骨架、材质、动作与镜头，可直接打开编辑/再次渲染。原片只是可选参考层。

场景使用标准 MakeHuman 变形骨架和项目的 IK 控制，不是已生成的 Rigify 控制架。男/女模板可供用户选择，不自动声称识别了人物性别或恢复了原片身份、脸型与服装。

手脚 IK 修改默认在当前帧前后最多四帧过渡，区间外保留原动作，不把一次修改扩展为整段固定手势。手部预设检查过渡区间的前臂/躯干与人物相交，并尝试向胸前安全位置调整；无法消除时明确返回剩余问题。目标不可达时返回实际位置误差，不能视为准确到达。

逐帧修正进行两轮遍历，每帧最多三次有界尝试，质量 JSON 记录修正次数和剩余帧。人物间距离按实际变形网格范围计算；遮挡帧也保留完整手臂关键帧，避免插入修正关键帧后影响邻帧。检测范围是人体之间的表面交叉以及前臂/躯干区域，不覆盖所有身体自碰撞、衣物/道具、纯体积包含或接触关系真实性。修订重渲染会重新检查整个单镜头，生成该修订自己的质量报告、媒体时间轴和清单，不继承整片的零问题计数。人物相对深度和正交镜头仍有近似，单目估计、漏检和空景/局部镜头继续标注待复核。

## 结论

Blender 能渲染接近真人外形的白色人物。当前抽象外形主要来自人体几何和姿态表达：渲染器得到的是拼接部件与平面近似关节，而不是连续人体及真实三维动作。CLI / MCP 是控制方式，不能代替人体建模、姿态估计和相机求解。

采用“CLI 批量生产 + MCP 交互修正 + 共用 Blender 操作模块”。首先升级人体资产与动作驱动，再接 MCP；不把整段动画交给大模型逐帧自由建模。

## 接入前检查（对比依据）

以下条目记录升级前的问题，当前实现与验证范围见上方“当前使用”和 `output/cache/human_review/final-test-report.md`。

- `whiteblock/pipeline.py::run_blender_script` 已调用官方 `--background --factory-startup --python-exit-code 1 --python`，具备日志、超时、帧数校验、编码和归档流程。
- `whiteblock/blender_scene.py.template` 用球形部件和单独躯干拼接；部件骨基本挂在 Root，使用刚性部件权重。合并为一个对象不等于连续、正常蒙皮的人体。
- `whiteblock/pose_cleanup.py` 将关节 Y 深度设置为人物固定层、手臂设置为胸前安全层。它减少部分穿胸，但会压平姿态，无法恢复转身、前后伸手和真实接触。
- `whiteblock/analysis_worker.py` 记录 MediaPipe 的画面关键点，每秒约 8 次抽样，当前没有使用输出的 world landmarks 做三维骨架拟合；多人跟踪依赖鼻部距离和人脸裁切。
- 当前使用正交构图相机与 Workbench；增加分辨率不会补出人体轮廓和原片深度。
- 本机 CLI 实测为 Blender 5.1.2，`--version` / `--help` 返回成功。显卡为 RTX 4070 Ti SUPER，约 16 GB 显存。
- Blender 安装目录存在内置 Rigify 文件；MPFB 与 Blender MCP 未在所检查的 Blender 用户扩展目录中发现，也没有当前可调用的 Blender MCP 工具。Rigify 文件存在不代表已启用；MPFB 对 Blender 5.1 的完整兼容性仍需隔离实例实测。

## 第一优先：把人物做成人体

1. 建立本地人体模板库，候选使用 MPFB / MakeHuman 核心人体资产，包含连续的人体拓扑、头面轮廓、手脚与标准权重。生成男/女基础模板，后续按肩宽、身高及体型调整；默认使用简单白色服装轮廓，允许纯人体或用户导入已绑定资产。体型参数在镜头/人物级固定，避免逐帧缩放身体。
2. 优先采用模板自带的变形骨架，必要时用 Rigify 补充 IK/FK 控制；Root → 骨盆 → 脊柱 → 胸 → 颈/头，以及正常的手脚骨链。骨长固定，关节弯曲通过旋转和连续蒙皮实现，不能继续逐部件拉伸。
3. 保留原片观察和置信度，把 2D 关键点、可用三维估计及人体先验拟合到模板。输出根节点位移、骨骼旋转、相机参数、足部/手部接触标记。短时缺失进行受约束预测，长时缺失标记复核；不能把整条手臂直接隐藏或凭空补动作后标记准确。
4. 白模材质使用哑光白，EEVEE 作为默认预览，灯光与接触阴影表现体积；Cycles 作为精细选项。渲染模式选择与人体模型选择独立，先完成模型和动作，再比较渲染器。

可复用的基础模板优先采用 MakeHuman 核心 CC0 资产。MPFB 插件代码是 GPL；其他服装、头发等下载资产逐个检查许可。模板与插件版本、来源和哈希记录到资产清单。

## 第二优先：改正三维动作与穿模

### 可先落地的本地路径

记录 MediaPipe world landmarks 作为三维姿态初值；它们仍是相对人体的估计，不能直接当作真实世界人物位置或准确相机参数。结合画面重投影误差、固定骨长、关节活动范围、时序平滑和脚底接触拟合三维骨架。每个镜头独立求解，跨镜头维持人物资产和身份映射，避免硬拼成连续空间。

人物距离与遮挡使用可估计的深度与接触约束，减少对固定深度层的依赖。空景和身体特写采用独立的场景/局部重建状态，不让检测不到全身的镜头直接以空白替代完成。

### 更高质量的可选路径

通过独立的姿态求解适配器接入视频人体模型估计，再把身体参数/关节动作映射到可编辑模板。WHAM、GVHMR 属于候选评估对象，不能直接视为本项目已可用：

- WHAM 代码为 MIT，但流程依赖 SMPL 模型、权重及额外组件，需分别核对获取条件和许可。
- GVHMR 当前仓库代码限定教育、研究及非盈利用途，商用需要作者许可，不适合直接作为面向用户软件的默认引擎；其安装文档也包含 CUDA/Linux 环境步骤和需单独获取的人体模型。
- 本机 16 GB 显存有评估空间，具体显存、运行速度、Windows/WSL2 兼容性、多人/特写效果必须用实际样片证明，不承诺所有候选能原生 Windows 一键运行。

### 防穿模流程

骨架解剖约束和蒙皮修正先处理肩/肘/髋塌陷；随后检查非相邻身体区域、人物之间及道具的碰撞。需区分允许的接触、相邻网格和关节连续区域，不能把所有表面接近都当错误。

使用碰撞代理体做快速筛查，必要时检查已变形网格；通过 IK、根位移和姿态优化解消冲突，同时限制原片重投影偏差。衣物跟随骨架与必要的衣物碰撞单独处理。骨架动画人物不适合靠“开启刚体”解决穿模。逐镜头记录剩余问题位置与置信度，供 Agent 和用户复核。

## 第三优先：MCP 交互修正

第三方 `ahujasid/blender-mcp` 支持活跃 Blender 内执行操作、场景/视口检查，附带的资产下载和 AI 建模不作为本地白模反推必需步骤。实际版本需固定并用 Blender 5.1 隔离实例验证。

项目自身需要一个 MCP 客户端适配层，由软件内部的 Eggfans Agent 调用。只把 MCP 配进 Codex，不会自动让软件内 Agent 获得 Blender 工具。

优先注册具体业务操作，例如：`get_scene_summary`、`get_preview`、`load_human_template`、`fit_actor`、`retarget_motion`、`set_ik_target`、`set_camera`、`check_intersections`、`render_preview`、`save_revision`。背后使用固定实现，与 CLI 共用代码；软件 Agent 继续不开放自由编码工具。

第三方通用 MCP 常用自由 Python 执行能力；不能把它原封不动当作项目 Agent 的工具权限。可包装可信操作，或编写只接受业务操作的本地 Blender 插件。后者更适合长期嵌入软件，前者适合快速验证交互体验。

连接只面向本地实例并标识会话/项目/修订。业务操作返回任务 ID、阶段、日志、取消与结果；MCP 断开后已有 CLI 任务可独立完成。对同一项目使用单写入队列，交互修订另存，防止实时修改与批量渲染相互覆盖。

当前模板的 `read_factory_settings(use_empty=True)` 只适用于隔离的批量构建。接入活跃 Blender 后必须改成导入或更新指定项目集合，不能在用户编辑现场执行清空场景。

修订渲染完成后加入现有白模仓库，保留旧版预览与原工程；新的完整视频只有在镜头汇总和媒体校验后标记完成。

## 实施与验收顺序

1. 人体模板验证：男/女白模站姿及屈肘、抬臂、坐姿，在正面/侧面/背面确认连续轮廓、权重和关节变形，保存可编辑模板。
2. 选原片一个有可靠人物的 3–5 秒镜头，驱动同一人体模板，比较人体比例、原片构图、骨长稳定、肩肘蒙皮和穿胸。先证明肉眼可见的外形与动作提升，再扩展全片。
3. CLI 全片批量验证：镜头数、帧率/比例/时长、工程、日志、失败恢复、仓库入库。空景/特写独立验收，不把未处理区域宣称完整重建。
4. MCP 交互验证：在软件 Agent 中直接说“把这只手移到胸前”“调整镜头”“复核这一段穿模”，确认本地 Blender 执行、视口反馈、版本保存和重渲染入库。
5. 模型求解增强：若第一条本地路径仍存在明显三维错误，再按可用许可与实测效果选择视频人体求解器；不能只靠升级渲染器掩盖动作错误。
