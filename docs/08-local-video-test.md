# 本地原片一键白模测试与当前边界

一键按钮现在调用统一的 `whiteblock.pipeline.one_click_convert`，不再为任何视频套用默认方块。流程是：只读复制原片到 `output/input` → 本地逐帧镜头切分 → 本地 MediaPipe 多区域姿态采样与镜头内跟踪 → Blender 可编辑人物部件动画 → 按原片比例渲染各镜头 → ffmpeg 合并预览并核验时长和帧数。

每次转换使用独立批次：项目在 `output/projects`，分析、运行日志与渲染缓存在 `output/cache`，每镜头 `.blend`、MP4、规格、脚本、manifest 和完整 `whiteblock_preview.mp4` 在 `output/exports/<批次 ID>`。完成页提供播放预览和打开输出文件夹，显示待复核镜头。原片不覆盖；失败会记为 failed；无可用人物姿态时不会生成默认方块并报成功。

此次原片约 30 秒、720×1280、24 fps，共 721 个视频帧，自动切分为 10 个镜头。真实桌面按钮测试已完成本机 Blender 5.1.2 渲染，输出 360×640、24 fps、721 帧的竖屏预览。人物代理来自视频关键点，源文件 SHA-256 保持一致。测试没有调用 Eggfans、上传视频或消耗模型 API 额度。

当前结果是用于动作、节奏和构图检查的**近似人物白模**。正交相机、相对深度为近似；尚未实现真实摄像机运动求解、完整背景、道具或骨骼绑定。该原片的两个吊灯镜头和一个胸口特写未检测到可靠完整人体，保留时间段并标记待补充。不能把此结果作为完整视频场景重建验收通过。

本机 D:\Python 的 MediaPipe 0.10.9 已含所需离线模型。为避免全局 NumPy 2 和 protobuf 5 与旧版 MediaPipe 冲突，姿态 worker 使用项目 `.venv-pose`（system-site-packages），隔离安装 NumPy 1.26.4、protobuf 3.20.3；系统环境未被替换。若移到其他电脑，须预先配置兼容的本地姿态依赖及模型，一键模式不会自动下载模型。

回归覆盖：无角色时不凭空生成代理、竖屏比例、相同颜色但不同构图的镜头切换、无人画面不会产生人物、真实 Blender 干净场景、动画位置变化、非第 1 帧开始的编码，以及桌面失败状态恢复。
